# Architecture

`src/main.cpp` owns the window, controller, config, and preset UI lifecycle. `src/ui` renders Dear ImGui panels and sends validated user actions to the controller. `src/app` owns engine state, diagnostic messages, and bounded single-producer/single-consumer exchanges. `src/audio` owns a native PipeWire context, endpoint registry, effective-link verification, separately targeted capture/playback streams, and a bounded clock-adapting bridge. `src/dsp` owns the sample processor and effects. `src/persistence` handles versioned JSON away from audio callbacks.

The signal path is capture channel → preallocated bridge → input gain → optional gate → monophonic octave-down → tone → optional compressor → optional saturation → wet/dry mix → output gain → mute → final -1 dBFS clamp → mono or duplicate stereo playback. The dry path is direct because this octave method has no fixed delay to align against. Parameter snapshots are validated on the UI thread, sent through a bounded queue, and consumed by the playback process callback. Meter snapshots move the other way. Callbacks use preallocated storage and do no file I/O, window operations, or logging.

The octave-down effect uses the system Rubber Band R3 engine in real-time, short-window mode at a 0.5 pitch scale. `OctaveShifter` feeds 128-frame blocks and drains the engine into a preallocated output queue. The output is entirely pitch shifted; no guitar signal or synthesized low voice is mixed into it. The user preferred this engine's level-matched render over the in-house granular and oscillator versions. The earlier crossfaded-delay candidate and a revised granular version sounded distorted. The engine's measured onset on the supplied recording is about 85 ms in the offline streaming path, before capture and playback, so the 20 ms physical target is not met by the current algorithm.

PipeWire source and sink nodes are listed independently. Each stream has its own explicit target and no-fallback/no-move policy. The controller checks effective graph links before setting `route_verified`, and playback outputs silence without that flag. It does not change desktop defaults, graph clock settings, or other application routes. The bridge has a bounded sample queue and a small adaptive read ratio for independent stream clocks; excess or missing samples are counted as overruns/underruns. Requested rate and buffer may differ from observed values. Route loss returns to a muted diagnostic state.

Latency has several sources: capture and playback hardware, PipeWire scheduling and conversion, bridge fill, and the octave engine's window and output buffering. The app currently displays only observed stream settings and a single-buffer estimate. A physical loopback measurement with full wet octave processing is still required for an end-to-end value; the offline streaming delay already exceeds the 20 ms target.
